1-3 · 폴더 구조

blog-reply 저장소

blog-reply/              ← git 저장소 · Orca가 여는 폴더
├─ CLAUDE.md             ← 설계도 · 벽에 붙은 판 (Codex는 AGENTS.md)
├─ scripts/
│  ├─ login.py           ← 최초 1회 · 직접 로그인 → 로그인 상태 저장
│  ├─ collect.py         ← 댓글 읽기 → comments.json
│  └─ post.py            ← approved.json 받아 답글 등록
├─ automations/
│  ├─ morning.md         ← 09:00 자동화 지시문 원본
│  └─ evening.md         ← 18:00 자동화 지시문 원본
└─ web/                  ← 승인 · 대시보드 (Next.js) → Vercel 배포
~/.blog-reply/auth.json  ← 로그인 상태 · 저장소 밖 고정 위치

핵심scripts = 손 · automations = 지시문 · web = 화면 · 장부 = Supabase

auth.json을 저장소 밖에 두는 이유: Orca는 실행마다 작업 폴더(worktree)를 새로 만들 수 있고, git에 안 올린 파일은 새 폴더에 없음.

# 블로그 답글 비서
## 구조  scripts = 브라우저 조작만 · 장부 읽기·쓰기 = Supabase MCP · web = 승인 화면
## 장부  comments · status: new → drafted → approved → posted | skipped
## 규칙
- 비밀번호 코드 기록 금지 · 로그인 상태 = ~/.blog-reply/auth.json
- 내 블로그 글만 대상 · 다른 블로그 접근 금지

## 합격 조건
1. 같은 댓글에 답글 2번 금지 (comment_id · 게시 직후 posted)
2. approved 아닌 댓글 게시 금지
3. 실패 시 멈추고 실패 사유를 장부 note 열과 실행 기록에 남김

4-1 · 지시문 파일

아침 · 저녁 지시문

# automations/morning.md · 매일 09:00
1. python scripts/collect.py 실행
2. comments.json을 Supabase MCP로 comments에 추가 (있는 comment_id 건너뛰기)
3. status new 댓글마다 설계도 말투로 초안 작성 → drafted
4. 처리 건수 한 줄 보고 · 실패 시 note 열에 사유
# automations/evening.md · 매일 18:00
1. Supabase MCP로 status approved 조회 → approved.json (하루 상한 10건)
2. python scripts/post.py approved.json 실행
3. 성공 건 즉시 posted · posted_at 기록
4. 실패 건 note 열에 사유 · 처리 건수 한 줄 보고

핵심지시문 = 파일로 보관 · Orca에는 "automations/morning.md 대로 실행" 한 줄

post.py는 수업 중 에이전트에게 요청: "approved.json 받아 30~90초 간격으로 답글 등록, --dry-run 지원". 실제 게시 전 dry-run 1회 필수.
